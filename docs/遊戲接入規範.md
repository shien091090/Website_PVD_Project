# 網頁遊戲接入規範（PVD計畫網站）

給要放上 PVD計畫網站的網頁遊戲遵守。可直接併入 game-studio-lab 的 RD 規範。

## 一、本機儲存（localStorage / sessionStorage / IndexedDB / cookie）

所有遊戲和網站在同一個網址底下，共用同一份瀏覽器儲存空間。

1. **鍵名格式：`<遊戲代號>:<用途>`**，例如 `bubble-tempo:best`、`bubble-tempo:muted`。
   - 遊戲代號＝網站網址用的代號（英文小寫加連字號），一款遊戲一個，定了不改。
   - 用途用英文小駝峰：`best`、`totalGames`、`muted`、`seenGuide`、`playerId`。
2. **鍵名不放版本號。** 版本號放進鍵名（如 `bcv19_`），每次改版玩家的最高分、靜音設定都會歸零。資料格式真的要改時，另存一個 `<遊戲代號>:schema` 記格式版本，讀到舊格式就轉換或捨棄。
3. **`pvd:` 開頭保留給網站**，遊戲不得使用。
4. **只碰自己前綴的鍵**：不可呼叫 `localStorage.clear()`，不可列舉並刪除別人的鍵。
5. **IndexedDB 資料庫名稱、cookie 名稱同樣加 `<遊戲代號>:` 前綴**（cookie 不能用冒號，改用 `<遊戲代號>_`）。
6. 讀寫一律包 try/catch，儲存空間不能用（無痕、App 內建瀏覽器）時遊戲照樣能玩。
7. **中途存檔（離開後回來接著玩）**：目前 4 款都沒有。之後要做的話，鍵名用 `<遊戲代號>:resume`，一局結束或重開時刪掉。

## 二、試玩紀錄

- **網站版不能下載任何檔案到玩家電腦。** 開發測試用的「一局結束下載試玩紀錄」機制在網站版整個移除。
- 網站不收集遊戲內的試玩紀錄。

## 三、與網站溝通（postMessage）

遊戲在網站裡是放在 iframe 中執行。

| 方向 | 訊息 | 說明 |
|---|---|---|
| 網站 → 遊戲 | `{type:'pvd:pause'}` | 手機轉回直拿、分頁被切走時送出。遊戲要暫停（含音效） |
| 網站 → 遊戲 | `{type:'pvd:resume'}` | 恢復。遊戲可以選擇顯示「點擊繼續」而不直接開跑 |
| 遊戲 → 網站 | `{type:'pvd:level-clear', level}` | （必送）單關通關，`level` 是第幾關（從 1 起的整數）。時機見下方「通關通知」 |
| 遊戲 → 網站 | `{type:'pvd:game-clear'}` | （必送）全局通關，最後結算畫面出現時送一次。時機見下方「通關通知」 |
| 遊戲 → 網站 | `{type:'pvd:progress', progress}` | （可選）載入進度，`progress` 為 0～1。有送的話網站的載入畫面會顯示百分比，並等 `pvd:loaded` 才收起 |
| 遊戲 → 網站 | `{type:'pvd:loaded'}` | （送了 `pvd:progress` 就必送）遊戲檔案都載完、可以開始玩 |

送給網站一律用 `window.parent.postMessage(msg, location.origin)`；收訊息時檢查 `event.origin === location.origin`。

### 通關通知

網站用這兩種通知統計「各關通關時間」與「全局通關時間」。時間由網站計算（只算實際在玩，暫停、分頁切走不算），遊戲只要在對的時間點送出通知，不用自己算時間。舊的 `pvd:finish`（玩完一局）已停用，網站不再收。

- **單關通關**：玩家真的過了某一關才送。失敗、重試、從選單重來、放棄都不送；同一關反覆失敗後才過，只在過關那次送一次。網站記錄的時間是從上次單關通關（或開始玩）到這次，中間失敗重試的時間都算進這一關。
- **全局通關**：所有關卡都過完、最後結算畫面跳出來時送一次（全局通關畫面通常緊接在最後一關的單關通關之後，兩種都要送）。網站記錄的時間是從開始玩累計到這次，之後兩種計時都歸零。
- 同一個時間點只送一次，不要在畫面每一幀或重複進入結算畫面時重送。

各款的時間點：

| 遊戲 | 單關通關（`level`） | 全局通關 |
|---|---|---|
| 接力吉尼（jelly-jinni，5 關） | 每過一關，`level` 1～5；3 條命用完不送 | 第 5 關過完、進入結局畫面 |
| 魂匠守衛者（soul-smith-defense，4 關） | 每關勝利，`level` 1～4；失敗不送 | 第 4 關勝利、出現結算畫面 |
| 來馬戲團（dungeon-zoo，4 天） | 每過一天，`level` 是第幾天 1～4 | 4 天跑完、出現總結算畫面 |
| Bubble Tempo（bubble-tempo，3 關） | 每過一關，`level` 1～3（第 3 關播完一輪曲子即過關）；血量歸零不送 | 第 3 關過完、恭喜過關過場後出現結算畫面 |

## 四、檔案與畫面

1. 入口是資料夾裡的 `index.html`，所有資源用相對路徑。
2. 單一檔案不超過 25MB。
3. 畫面高固定 720，中間 1280×720 是設計區。電腦遊戲框是 16:9，遊戲寬固定 1280；手機橫拿時遊戲框填滿畫面、不指定比例，遊戲依螢幕長寬比自己決定寬度（1280～1680，即 16:9～21:9）。遊戲畫布照自己的寬高比在 iframe 裡等比縮放、置中、不裁切，比例不合的地方自然留黑邊（不要假設視窗大小）。
4. 不改動上層頁面（不碰 `window.top`、不改網址、不開新視窗）。
5. 每款都要支援手機：觸控操作，且遊戲區內的拖曳不能捲動頁面。

## 五、目前 4 款的狀況（2026-10-29 查）

| 遊戲 | 目前鍵名 | 要改的 |
|---|---|---|
| BubbleCatcher | `bcv19_playerId` 等 7 個 | 鍵名改格式（保留舊值轉移）；移除試玩紀錄下載 |
| DungeonZoo | `gamelog-WebGame_DungeonZoo-pending`（暫存沒下載完的紀錄） | 移除試玩紀錄下載，這個鍵跟著拿掉 |
| GhostEchoV2 | 沒用本機儲存 | 移除試玩紀錄下載 |

4 款目前鍵名彼此不會撞，網站第一階段不用等這些修改；只有「移除試玩紀錄下載」是上線前必做。

# 網頁遊戲接入規範（PVD計畫網站）

給要放上 PVD計畫網站的網頁遊戲遵守。可直接併入 game-studio-lab 的 RD 規範。

## 一、本機儲存（localStorage / sessionStorage / IndexedDB / cookie）

所有遊戲和網站在同一個網址底下，共用同一份瀏覽器儲存空間。

1. **鍵名格式：`<遊戲代號>:<用途>`**，例如 `slime-tetris:best`、`bubble-catcher:muted`。
   - 遊戲代號＝網站網址用的代號（英文小寫加連字號），一款遊戲一個，定了不改。
   - 用途用英文小駝峰：`best`、`totalGames`、`muted`、`seenGuide`、`playerId`。
2. **鍵名不放版本號。** 版本號放進鍵名（如 `bcv19_`），每次改版玩家的最高分、靜音設定都會歸零。資料格式真的要改時，另存一個 `<遊戲代號>:schema` 記格式版本，讀到舊格式就轉換或捨棄。
3. **`pvd:` 開頭保留給網站**，遊戲不得使用。
4. **只碰自己前綴的鍵**：不可呼叫 `localStorage.clear()`，不可列舉並刪除別人的鍵。
5. **IndexedDB 資料庫名稱、cookie 名稱同樣加 `<遊戲代號>:` 前綴**（cookie 不能用冒號，改用 `<遊戲代號>_`）。
6. 讀寫一律包 try/catch，儲存空間不能用（無痕、App 內建瀏覽器）時遊戲照樣能玩。
7. **中途存檔（離開後回來接著玩）**：目前 4 款都沒有。之後要做的話，鍵名用 `<遊戲代號>:resume`，一局結束或重開時刪掉。

## 二、試玩紀錄

- **網站版不能下載任何檔案到玩家電腦。** 開發測試用的「一局結束下載試玩紀錄」機制在網站版整個移除。
- 網站不收集遊戲內的試玩紀錄。

## 三、與網站溝通（postMessage）

遊戲在網站裡是放在 iframe 中執行。

| 方向 | 訊息 | 說明 |
|---|---|---|
| 網站 → 遊戲 | `{type:'pvd:pause'}` | 手機轉回直拿、分頁被切走時送出。遊戲要暫停（含音效） |
| 網站 → 遊戲 | `{type:'pvd:resume'}` | 恢復。遊戲可以選擇顯示「點擊繼續」而不直接開跑 |
| 遊戲 → 網站 | `{type:'pvd:finish'}` | （可選）玩家完成一局時送出 |

送給網站一律用 `window.parent.postMessage(msg, location.origin)`；收訊息時檢查 `event.origin === location.origin`。

## 四、檔案與畫面

1. 入口是資料夾裡的 `index.html`，所有資源用相對路徑。
2. 單一檔案不超過 25MB。
3. 畫面以 21:9 橫式為準，建議尺寸 1680×720；遊戲畫布要跟著 iframe 大小等比縮放（不要假設視窗大小，不要用固定像素大小畫）。
4. 不改動上層頁面（不碰 `window.top`、不改網址、不開新視窗）。
5. 支援手機的遊戲：觸控操作，且遊戲區內的拖曳不能捲動頁面。

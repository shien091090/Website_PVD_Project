# PVD計畫網站 部署與維護說明

## 一、使用者要做的事（只做一次）

### 1. 申請帳號
| 服務 | 網址 | 要交給實作者的東西 |
|---|---|---|
| Cloudflare | https://dash.cloudflare.com/sign-up | 帳號 ID（首頁右側「Account ID」）、API token（見下） |
| Cloudflare Zero Trust | 登入後左側選單「Zero Trust」→ 選 Free 方案 → 取團隊名稱 | 團隊名稱（例如 `meraklika`）。可能要求填付款方式，免費方案不扣款 |
| PostHog | https://posthog.com/signup | 區域（US 或 EU）、專案金鑰（`phc_` 開頭，公開）、專案 ID、Personal API key（見下） |
| 後台 email | — | 只有這個 email 能登入後台 |

### 2. 建立 Cloudflare API token
My Profile → API Tokens → Create Token → Create Custom Token，權限：
- Account → Cloudflare Pages → Edit
- Account → D1 → Edit
- Account → Turnstile → Edit
- Account → Access: Apps and Policies → Edit

### 3. 建立 PostHog Personal API key
Settings → Personal API keys → Create，範圍勾：Feature flag（寫）、Insight（寫）、Dashboard（寫）、Query（讀）。

### 4. 把秘密交給實作者（不要貼在對話裡）
在 `E:\Project\PVDWebsite\` 新增 `.secrets.env`（不會上傳 GitHub）：
```
CLOUDFLARE_API_TOKEN=...
CLOUDFLARE_ACCOUNT_ID=...
ACCESS_TEAM=團隊名稱
ADMIN_EMAIL=你的email
POSTHOG_PERSONAL_KEY=...
POSTHOG_PROJECT_ID=...
POSTHOG_HOST=https://us.posthog.com
```

### 5. 在 Cloudflare 網頁上連接 GitHub（API 做不到，要本人點）
Workers & Pages → Create → Pages → Connect to Git → 授權 GitHub → 選 `Website_PVD_Project`：
- 專案名稱：`pvd-project`
- Production branch：`main`
- Build command：留空
- Build output directory：`site`

## 二、實作者用腳本做的事
1. `node tools/cf-setup.mjs`：建 D1 並套資料表、建 Turnstile、建 Access 後台登入、設定秘密變數。完成後依提示改 `site/js/config.js` 的 `turnstileSiteKey`。
2. `node tools/posthog-setup.mjs`：建主題 AB 旗標 `theme-ab` 與儀表板「PVD計畫」。完成後把 `site/js/config.js` 的 `posthogKey` 填專案金鑰、`posthogHost` 依區域填 `https://us.i.posthog.com` 或 `https://eu.i.posthog.com`。
3. commit 並推送，Cloudflare 會自動部署。兩支腳本都可以先加 `--dry-run` 看會做什麼。

## 三、日常維護

| 要做的事 | 怎麼做 |
|---|---|
| 改開發頁 | 編輯 `site/content/develop.md`（檔案開頭有格式說明），推送即更新 |
| 換遊戲版本 | 遊戲改好後執行 `npm run sync-games`（只換一款：`npm run sync-games -- slime-tetris`），推送 |
| 換遊戲名稱、介紹、圖示、主色 | 改 `site/js/games.js`；圖示放 `site/media/games/` 並在 `icon` 填路徑 |
| 換首頁影片 | 替換 `site/media/` 的檔案，改 `site/js/config.js` 的 `VIDEO`（接播秒數、標題位置；有直版就填 `portrait`）；換完要在電腦與手機各看一次標題與影片銜接 |
| 設定投票時間、開新一輪、同票指定勝出 | 後台 `/admin/` →「投票」 |
| 刪留言、鎖留言 | 後台 `/admin/` →「留言」 |
| 產生社群貼文連結 | 後台 `/admin/` →「連結產生」 |
| 看數據 | PostHog → Dashboards →「PVD計畫」 |
| 測試主題 | 網址加 `?theme=dark` 或 `?theme=light`（不影響分組，會出現切換鈕） |

## 四、本機開發
```
npm install
copy .dev.vars.example .dev.vars
npm run db:local
npm run dev          # http://localhost:8788 ，後台 http://localhost:8788/admin/ 免登入
npm test             # 單元測試
npm run e2e          # 瀏覽器測試（需本機 Chrome）
```

## 五、分階段測試清單（照設計文件 §7）

1. **靜態網站**：各頁在電腦（Chrome/Edge/Safari）、iPhone Safari、Android Chrome、Threads 與 FB 的 App 內瀏覽器都正常；首頁影片銜接不跳；手機直拿出現轉向提示；遊戲裡拖曳不會捲動頁面。
2. **留言與後台**：兩台裝置互看留言；連發會被擋；後台刪除後前台消失；鎖住後顯示「留言功能暫時無法使用」；用別的 email 進不了後台。
3. **投票**：在後台開一個 10 分鐘的測試輪：投、改投、換瀏覽器算新人、時間到自動切結果；投票中看網頁原始碼與網路請求都查不到票數；同票時顯示「結果統計中」，後台指定後出現勝出卡。
4. **數據與 AB**：用幾條產生的連結進站，在 PostHog「Activity」看到事件帶正確來源、裝置、主題；兩種主題都有人被分到；儀表板有數字。
5. **封測**：10–20 位朋友玩幾天；之後在後台刪掉測試輪與測試留言（或請實作者清空資料庫）。
6. **正式上線**：後台設定第一輪正式起訖，發布社群連結。

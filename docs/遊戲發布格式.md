# 遊戲發布格式（交給 PVD計畫網站的 release 資料夾）

網站用同步工具讀遊戲專案的 `release/`，複製進網站並更新遊戲資料。這份規定 `release/` 要長什麼樣子，同步工具照這份檢查，不合就停下並列出原因。

遊戲本身要守的規則（儲存鍵名、不能下載檔案、iframe 內的行為）另見《遊戲接入規範》（`docs/遊戲接入規範.md`）。

## 一、資料夾結構

```
release/
├─ game/                 ← 會原樣放上網站，任何人都下載得到
│  ├─ index.html         ← 入口
│  └─ ……                 ← 只放遊戲執行時會載入的檔案
└─ assets/
   ├─ info.json          ← 網站讀這份更新遊戲資料（必要）
   ├─ icon.png           ← 遊戲圖示（必要）
   ├─ banner.png         ← 遊戲橫幅（必要）
   ├─ pattern.png        ← 主題色圖樣（必要）
   └─ trailer.mp4        ← 30 秒介紹影片（選填，還沒做好可以先不放）
```

網站只讀 `release/game/` 與 `release/assets/` 底下上面列的檔案，其他東西（方案稿、選擇頁、介面描述、素材資訊.md 等）網站不讀。這些是製作過程的工作檔，建議移出 `release/`，讓 `release/` 只剩交付物；放著也不會出錯。

## 二、`game/`：只放執行時要用的

`game/` 整包公開，放進去的東西任何人都打得開。

**要放：**
- `index.html` 與它載入的程式、圖片、音樂音效
- 音樂音效的授權來源 `audio/credits.md`（免費素材常要求標示出處，這個例外保留）

**不要放：**
- 開發文件：`style.md`、`sound.md` 等任何 `.md`（`credits.md` 除外）
- 沒被遊戲載入的檔案，例如美術參考用的 `ref-objects.js`
- 試玩紀錄、測試腳本、設計稿

**檢查規則（同步工具會擋）：**
1. 有 `index.html`
2. 除了 `audio/credits.md`，沒有其他 `.md` 檔
3. 單一檔案不超過 25MB
4. 程式裡沒有下載檔案的寫法（`download`、`createObjectURL`）

## 三、`assets/info.json`

網站上的標籤、遊戲玩法、介紹、時長、主色、支援裝置都從這份讀。網站不顯示遊戲名稱，原本寫名稱的地方一律改用標籤。格式：

```json
{
  "code": "dungeon-zoo",
  "tag": "地城＋經營",
  "pitch": "地城裡抓怪物，帶回馬戲團表演賺錢",
  "intro": "深入地下城戰鬥、捕捉怪物，再送牠們上馬戲團舞台賺取掌聲和收益。攻略越深，陣容越熱鬧，一起炒熱全場氣氛吧！",
  "time": "18–30 分鐘",
  "color": "#f29cac",
  "textColor": "#2d2144",
  "ratio": "16:9",
  "mobileRatio": "16:9-21:9"
}
```

| 欄位 | 必要 | 說明 |
|---|---|---|
| `code` | 必要 | 遊戲代號，英文小寫、數字、連字號。必須是網站已有的代號（`bubble-tempo`、`dungeon-zoo`、`jelly-jinni`、`soul-smith-defense`），上線後不改 |
| `tag` | 必要 | 核心玩法標籤，用「＋」（全形）串 2–3 個玩法類型，例「塔防＋組裝」。網站上原本放名稱的地方都顯示它：遊戲清單橫幅左上、介紹標題、投票選項、投票結果 |
| `pitch` | 必要 | 遊戲玩法一句話，20 字內、越短越好，例「塔防單位可拆解組裝，自由搬移能力」。顯示在介紹標題正下方，跟時長同一個框 |
| `name` | 選填 | 遊戲名稱，只給後台和讀屏用，網站前台不顯示；沒給就用 `tag` |
| `intro` | 必要 | 1–2 句，建議 30–60 字。網站目前不顯示，先留著備用 |
| `time` | 必要 | 「X–Y 分鐘」，中間用 en dash（–） |
| `color` | 必要 | 遊戲主色，`#` 加 6 碼十六進位 |
| `textColor` | 必要 | 主色上的字色，`#2d2144`（深色）或 `#ffffff`（白色） |
| `ratio` | 必要 | 電腦上的遊戲畫面比例，例「16:9」。網站電腦遊戲框是 16:9，比例不同時遊戲自己加黑邊 |
| `mobileRatio` | 必要 | 手機上的遊戲畫面比例範圍，例「16:9-21:9」；固定比例就寫一個，例「16:9」。網站手機遊戲框填滿畫面，遊戲依螢幕自己決定寬度 |

- 多出來的欄位網站會忽略，不會出錯（例如 `time_estimated`）。
- **操作方式說明不用給**：網站不顯示，操作由遊戲內的教學教玩家。

## 四、圖片

| 檔案 | 規格 |
|---|---|
| `icon.png` | 512×512 PNG，背景不透明，不放文字。網站會裁成圓角加粗框，重要內容放中間約 80% |
| `banner.png` | 1680×720 PNG（21:9），背景不透明。當試玩頁遊戲清單的按鈕（電腦與手機都是），用角色、場景營造遊戲氛圍，**不放任何文字**（包含遊戲名稱）。網站會原比例縮小顯示、不裁切；左上角（左邊 60%、上方 25%）會疊標籤膠囊，左下角（左邊 30%、下方 25%）會壓時長小標籤，這兩塊不要放重要內容 |
| `pattern.png` | 256×256 PNG，背景不透明，可無縫拼接的圖塊。底色就是 info.json 的 `color`，上面畫這款遊戲自己的紋路（例：泡泡、音符、磚塊、星點），紋路要淡、對比低，不放文字和角色。網站把它以 128×128 重複鋪滿，當試玩頁遊戲介紹頂端的色帶（電腦約 500×76、手機約 400×46）；色帶左下會被遊戲圖示蓋住一塊 |

## 五、介紹影片 `trailer.mp4`（選填）

網站在試玩頁遊戲清單的橫幅右下角放一顆「30 秒介紹」按鈕，點了跳出置中彈窗播放（不是全螢幕，最寬約 880px，手機約螢幕寬）。還沒有影片的遊戲不顯示這顆按鈕。

| 項目 | 規格 |
|---|---|
| 長度 | 30 秒左右，不超過 35 秒 |
| 畫面 | 16:9 橫式，1280×720（720p）。彈窗是 16:9，比例不同會出現黑邊 |
| 格式 | MP4（H.264 影像 + AAC 聲音），手機和所有瀏覽器都能直接播 |
| 檔案大小 | 建議 10MB 以內（30 秒 720p 大約 3–8MB），上限 25MB |
| 聲音 | 可以有。玩家點了才播放，瀏覽器允許出聲 |
| 字幕 | 需要說明文字就直接燒進畫面，網站不另外疊字幕 |

- 影片跟網站放在一起，不經過 YouTube 等第三方。
- 開頭第一格就是彈窗載入時先看到的畫面，不要是全黑。

## 六、同步

在網站 repo 跑 `npm run sync-games -- <代號>`，工具會：
1. 照上面規則檢查 `release/`，不合就停下並列出原因
2. 把 `release/game/` 複製成網站的 `site/games/<代號>/`
3. 把 `icon.png` 複製到 `site/media/games/<代號>.png`，`banner.png` 複製到 `site/media/games/<代號>-banner.png`，`pattern.png` 複製到 `site/media/games/<代號>-pattern.png`；有 `trailer.mp4` 就複製到 `site/media/trailer-<代號>.mp4`，沒有就把網站上舊的拿掉
4. 用 `info.json` 更新網站上這款遊戲的資料

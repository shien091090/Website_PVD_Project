# 遊戲發布格式（交給 PVD計畫網站的 release 資料夾）

網站用同步工具讀遊戲專案的 `release/`，複製進網站並更新遊戲資料。這份規定 `release/` 要長什麼樣子，同步工具照這份檢查，不合就停下並列出原因。

遊戲本身要守的規則（儲存鍵名、不能下載檔案、iframe 內的行為）另見《遊戲接入規範》（`docs/遊戲接入規範.md`）。

## 一、資料夾結構

```
release/
├─ game/                 ← 會原樣放上網站，任何人都下載得到
│  ├─ index.html         ← 入口
│  └─ ……                 ← 只放遊戲執行時會載入的檔案
└─ assets/
   ├─ info.json          ← 網站讀這份更新遊戲資料（必要）
   ├─ icon.png           ← 遊戲圖示（必要）
   └─ share.png          ← 分享預覽圖（可選，網站目前還沒用到）
```

網站只讀 `release/game/` 與 `release/assets/` 底下上面列的檔案，其他東西（方案稿、選擇頁、介面描述、素材資訊.md 等）網站不讀。這些是製作過程的工作檔，建議移出 `release/`，讓 `release/` 只剩交付物；放著也不會出錯。

## 二、`game/`：只放執行時要用的

`game/` 整包公開，放進去的東西任何人都打得開。

**要放：**
- `index.html` 與它載入的程式、圖片、音樂音效
- 音樂音效的授權來源 `audio/credits.md`（免費素材常要求標示出處，這個例外保留）

**不要放：**
- 開發文件：`style.md`、`sound.md` 等任何 `.md`（`credits.md` 除外）
- 沒被遊戲載入的檔案，例如美術參考用的 `ref-objects.js`
- 試玩紀錄、測試腳本、設計稿

**檢查規則（同步工具會擋）：**
1. 有 `index.html`
2. 除了 `audio/credits.md`，沒有其他 `.md` 檔
3. 單一檔案不超過 25MB
4. 程式裡沒有下載檔案的寫法（`download`、`createObjectURL`）

## 三、`assets/info.json`

網站上的遊戲名稱、介紹、時長、主色、支援裝置都從這份讀。格式：

```json
{
  "code": "dungeon-zoo",
  "name": "來馬戲團看一點大場面",
  "intro": "深入地下城戰鬥、捕捉怪物，再送牠們上馬戲團舞台賺取掌聲和收益。攻略越深，陣容越熱鬧，一起炒熱全場氣氛吧！",
  "time": "18–30 分鐘",
  "mobile": true,
  "color": "#f29cac",
  "textColor": "#2d2144",
  "ratio": "16:9"
}
```

| 欄位 | 必要 | 說明 |
|---|---|---|
| `code` | 必要 | 遊戲代號，英文小寫、數字、連字號。必須是網站已有的代號（`bubble-catcher`、`slime-tetris`、`dungeon-zoo`、`ghost-echo`），上線後不改 |
| `name` | 必要 | 遊戲名稱，跟遊戲開始畫面一致 |
| `intro` | 必要 | 1–2 句，建議 30–60 字 |
| `time` | 必要 | 「X–Y 分鐘」，中間用 en dash（–） |
| `mobile` | 必要 | 手機能不能玩：`true` 或 `false`。`true` 代表遊戲有觸控操作，且遊戲區內拖曳不會捲動頁面 |
| `color` | 必要 | 遊戲主色，`#` 加 6 碼十六進位 |
| `textColor` | 必要 | 主色上的字色，`#2d2144`（深色）或 `#ffffff`（白色） |
| `ratio` | 必要 | 遊戲畫面比例，例「16:9」。不是 16:9 的網站會加邊 |

- 多出來的欄位網站會忽略，不會出錯（例如 `time_estimated`）。
- **操作方式說明不用給**：網站不顯示，操作由遊戲內的教學教玩家。

## 四、圖片

| 檔案 | 規格 |
|---|---|
| `icon.png` | 512×512 PNG，背景不透明，不放文字。網站會裁成圓角加粗框，重要內容放中間約 80% |
| `share.png` | 1200×630 PNG，角色場景加遊戲名稱。可選，網站之後做單款分享時才會用 |

## 五、同步

在網站 repo 跑 `npm run sync-games -- <代號>`，工具會：
1. 照上面規則檢查 `release/`，不合就停下並列出原因
2. 把 `release/game/` 複製成網站的 `site/games/<代號>/`
3. 把 `icon.png` 複製到 `site/media/games/<代號>.png`
4. 用 `info.json` 更新網站上這款遊戲的資料
